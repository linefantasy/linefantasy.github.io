# 项目目录整理实施计划

**目标：** 按用户要求将根目录散落文件归类，更新引用，保留原功能、已有修改和历史证据。

**范围：** 仅本地文件结构维护，不实施后端，不提交、推送或部署。当前产品设计仍以迁移后的 `docs/design.md` 为唯一入口。

## 目录与步骤

- [x] 网站入口、CNAME、assets、data 移到 `public/`；头像移到 `public/assets/images/avatar.jpg`，网站 URL 结构保持 `/` 和 `/map.html`。
- [x] 设计与协作入口移到 `docs/`；参考资料移到 `docs/references/`；推送教程移到 `docs/guides/`；历史报告移到 `docs/verification/`；测试移到 `tests/`。
- [x] `.tmp` 过程证据按 QA、研究、临时脚本归入 `artifacts/`，逐文件核对哈希，不删除旧证据。新日志统一放 `artifacts/logs/`，整个 artifacts 不入 Git。
- [x] 同步生成器、测试、Markdown 链接和本地运行说明。根目录保留 README、Git 隐藏配置及目录。AGENTS 移到 docs 后由 README 明确引导读取。
- [x] 运行页面生成器及地图/主题检查，检查生成幂等、静态资源与文档链接，实际浏览器回归；更新当前交接并说明未验证的线上发布。

## 重点检查

页面和模块的相对路径、头像及默认图、manifest 数据路径、生成器输入/输出、原始资源哈希、历史证据位置、现有未提交文档内容和未跟踪教程均需保留。历史证据内嵌路径保持原始内容，由迁移清单提供位置映射；历史结果不作为本轮验证。
